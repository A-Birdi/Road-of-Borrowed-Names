# Expressive storytelling — Phase A: reconciled baseline and integration contract

The owner's addendum of 2026-10-03 (Harmony Cut-Ins, Expressive Characters, and Illustrated
Storytelling), §22 Phase A, together with its paired addendum of the same date (World Idle Life,
Character Mannerisms, and Animated Dialogue Portraits). Both are implemented on **one** actor and
mannerism system. This document maps what the first addendum assumes about its reference build onto
**the current source** of the task branch, lists every numbered requirement of §5–§21 as a ledger
(`HX1`…) and the paired addendum's requirements as `WI1`…, and fixes the module boundaries and APIs the
later workers build to. Companion documents in this folder:

| File | What it holds |
|---|---|
| `CONTRACT.md` (this) | baseline reconciliation (§3, Appendix A S1–S9), ledger HX1–HX70, module ownership and APIs, conflicts, risks |
| `HARMONY.md` | the four techniques: exact effects, current choreography and measured durations, the new timeline per playback setting, anticipation / signature / recovery silhouettes, rule protection |
| `GESTURES.md` | the 32 §11.2 primitives against the overworld sprite rig (what it can and cannot pose); the mannerism framework (profile schema, escalation from idle to cutscene, the paired addendum's idle categories, reuse policy); mannerism profiles for the player, the four companions and 71 recurring NPCs |
| `PORTRAITS.md` | the dialogue-portrait animation plan: the current renderer, expression-tag counts, eye-area readability problems (with captures), idle loops, lead-in cues per tag, per-character portrait mannerisms, reduced motion, caching |
| `REVIEW.md` | the paired addendum's full-game look-and-feel review from the source: 41 classified findings across all chapters and a table of all 91 maps |
| `SHOTS.md` | the §17.2 selections (one per chapter, the prologue rework) with §17.3 shot plans, and the audit of the personal questlines, long questlines, endings and The Pages We Keep |
| `SCENES.md`, `scenes.json` | the §16 scene-coverage manifest, generated by `node tools/scene_manifest.mjs` (1,392 entries; draft classifications) |

**Source identity.** Inspected: the task branch `claude/stoic-sagan-n3jvgk` at `20277f1` ("Merge the
top of the lighthouse…"). Nothing in `src/` was changed in this phase. The reference images
(the compact left-middle paired portrait over the Harbour Fog battle, and the larger preliminary
mockups) were viewed and are not committed. Only the compact one is a target; the preliminary ones
carry a slogan, a large heading and an invented "Expansive" control, none of which is to be copied (§3,
§4.2). The real setting is **Expanded** intentions (`intentDisplay: 'expanded'`).

**What was run here (Phase A).** `node tools/validate.mjs`, `node tests/run-unit.mjs`,
`node tools/scene_manifest.mjs` and the new `tests/unit/scene_manifest.test.mjs`; durations in this
document were computed by calling `RB.battleSeq.choreo.player()` in node on synthetic fx (no browser).
One short headless-Chromium page rendered the dialogue portraits for PORTRAITS.md (`docs/screenshots/
expressive/`); no browser test suite was run. Nothing here claims a browser-verified behaviour unless it cites an existing
REQUIREMENTS.md / VALIDATION.md entry, and those entries were **not re-run** in this phase.

### 3.1 Harmony busts — `RB.harmonyArt` (new `src/engine/38_harmony_art.js`, per-companion art in `38a_harmony_nao.js` … `38d_harmony_suzu.js`, player layers in `38p_harmony_player.js`)


### 3.2 Cut-in overlay — `RB.harmonyCutin` (new `src/ui/82d_harmony_cutin.js`) and a seam in `82_battle_seq.js`

**Lifecycle.** One instance at a time: `{ n (token), actionId, comp, look (snapshot), variant, rect, state, t0 }`
with `state ∈ inactive → entering → holding → fading → disposed`. Every callback checks `inst.n === cur.n`;
an old instance can never touch a newer one.

**Clock.** The battle's presentation clock — never `setTimeout` for the visible ramp. Seam in
`82_battle_seq.js` (owner of the clock, Skip and settle):
- a new cue type `cutin` handled in `fire1()`'s default branch (`if (instant) break;` already makes Instant
  and Skip produce no portrait): `RB.harmonyCutin.start(c, at)` with `c = { at, type: 'cutin', comp, d: { in, hold, out } }`;
- in `tick(t)` after `step()`: `RB.harmonyCutin && RB.harmonyCutin.frame(pt)` (keeps `80_combat.js` untouched);
- in `settle(why)` and `detach()`: `RB.harmonyCutin.dispose(why)` (covers Skip, hidden tab, watchdog, overlap,
  scene exit); hurried playback (×4) simply runs the ramp faster;
- `T.cutin = { normal: { in: 180, hold: 380, out: 220 }, fast: { in: 143, hold: 315, out: 229 } }` in
  presentation ms (Fast's clock runs ×1.43, so these are 100 / 220 / 160 ms of wall time).

**Who emits the cue.** `RB.partyChoreo.player()` for `plan.family === 'technique'`, at `at = t` (the
technique's own animation start), only when `ctx.comp` is set, the setting is On and `RB.harmonyCutin.can()`
(no dialogue/challenge/help layer open; a placement exists). One cue per technique, groups included.

**Surface.** A `<canvas class="cb-cutin" aria-hidden="true">` with `inert`, `pointer-events: none`, inserted
in the combat overlay root before `.cb-banner`; CSS `position: absolute; z-index: 3` (above `.cb-fx` = 1, below
`.cb-banner` = 6 and the menus); drawn with `imageSmoothingEnabled = false` at an integer CSS px per art px;
opacity from the clock; `display: none` and drawing stopped when not visible; removed at `disposed`.

**Placement (§5.3–§5.4).** `place()` runs at `start` and on `resize`/`orientationchange`/`ResizeObserver` of the
overlay (same instance, no replay):
1. collect protected rects (CSS px): `.cb-party`, `.cb-banner` (its `on` rect), `.intent` and `.cb-dock` unless
   withdrawn (`.cb-acting` without `.cb-keep` and the element off-screen/`visibility: hidden`), `.cb-foe [data-foe]`
   plates, creature boxes and the impact anchor from `RB.battleStage.stats().lay` × `cssPerArt()`, the party
   box `lay.party`, `.cb-skip`, `.kwcard`, `.cb-icard`, any open `.dlg`/challenge sheet; inflate each by 12 px;
2. try the standard variant at the default footprint (≈35 % × 26 % of the overlay's client rect, capped at
   42 % / 30 % / 12 % area) anchored to the left edge, vertically between the top information and the party;
3. slide it vertically on the left; 4. the compact variant (backing and particles reduced first);
5. otherwise no portrait for this action: `stats().fallbacks.push({ action, viewport, reason })`.
Never move or resize any UI surface, the stage, or the camera; never call `hold()`.

**API.**
```
RB.harmonyCutin.can()                 → boolean (setting, layers, a companion)
RB.harmonyCutin.start(cue, atPt)      → token | null (enters 'entering'; snapshots RB.equip.look(RB.game.s))
RB.harmonyCutin.frame(pt)             advance state by the presentation clock; draw
RB.harmonyCutin.dispose(why)          'settle' | 'skip' | 'hidden' | 'exit' | 'campaign' | 'error' | 'resize-invalid'
RB.harmonyCutin.state()               { state, token, actionId, comp, variant, rect, opacity } (tests)
RB.harmonyCutin.stats()               { started, disposed, fallbacks: [], maxLiveLayers, cache: harmonyArt.stats() }
```

**Setting.** "Harmony portrait flourish" On/Off, key `harmonyFlourish`, default `true` (one line in
`90_game.js defaultSettings()`; older settings records merge to On), row added with
`RB.ui.settings.addRows('learning', ({ sw }) => sw('harmonyFlourish', 'Harmony portrait flourish', '…'))` next to the
Battles rows (no edit to `55_settings.js`).

**Banner.** Unchanged: `playPlayer()` already shows "<player> & <companion> — <technique>" for the
technique's interval (`P.end`). The cut-in's rect excludes the banner's.

**Pets.** `RB.battlePets` already reacts to `present:action`; it may add a rally glance keyed on
`family === 'technique'` without adding duration (HX27).

### 3.4 Expressive actor system for overworld sprites — `RB.staging` (new `src/engine/52_staging.js`) with a pose layer in the sprite rig

**What the rig can pose today** (`32_spriteart.js`, 40 × 58 frame, foot anchor (20, 55)):

| Body part | Today | Needed for §11.2 |
|---|---|---|
| facing | 4 drawn directions (`left` = mirrored side), turn pivot `RB.sprites.view` (half turns through a side/front view for 90 ms, quarter turns settle 70 ms) | as is, plus a held "look" that does not change the facing |
| head | follows the body; a 1 px bob (idle `i0–i3`, walk); blink (`…b` frames); old people stoop (`age: 'old'` lowers the face row) | lowered head (1–2 px), tilt, eyes-only glance (iris 1 px left/right/up/down), nod (2-key) |
| arms/hands | hang by the body; `arms.R/L` swing −1/0/+1 with the walk (`handsFB`, `armSide`) | hand to chin / chest / forehead / mouth, point, open palm, both hands forward, arms folded, fingers counting (2–3 px hand shapes) |
| torso | 1 px bob; garments sway with the walk | lean in/back 1–2 px, shoulders lowered/raised, small bow (head and torso rows shifted) |
| legs | stand, eight-phase walk | half-step (sub-tile offset), kneel/bend (lower body redrawn) |
| held objects | accessories drawn as layers (`lamp`, `cane`, `basket`, `book`, `bottles`, `satchel`, `toolbelt` …) | a held object follows the hand that holds it during a gesture |
| overlays | `a.overlay(c, fx, fy, t)` (the field action's raised hand and brush, `57_weave.js`), `a.dy` (knee dip), emote bubbles (`60_render.js EMOTE`: `! ? ... note heart sweat anger`) | the overlay hook is the precedent for bespoke, per-character pose art |

So: **facing and bubbles only**. Every §11.2 primitive except turn-and-listen needs the pose layer
(GESTURES.md §2 has the per-primitive table).

**Pose layer.** Extend `poseOf(frame)` to parse pose keys `p:<pose>:<k>` (e.g. `p:chin:2`, `p:kneel:1`) into
arm targets (per side: `hand: 'chin'|'chest'|'forehead'|'mouth'|'point'|'palm'|'forward'|'folded'|'count'|'hip'`
with a 2-step reach), `head: { dy, tilt, eyes }`, `torso: { lean, shoulders }`, `legs: 'kneel'|'halfstep'`; new
draw paths in `armsFB`/`armSide` for bent arms, a lowered-head row shift and the kneel. Pose tables in a new
`src/engine/32g_spritepose.js`. Art is cached per look and pose key exactly like the existing frames
(`SP.getArt`), so a pose costs one build per look.

**Staging service.**
```
RB.staging.cue(actorId, gesture, o)   o: { target (actor id | 'pc' | 'prop:<map prop index>' | 'x,y'), hold: true|false,
                                      intensity: 1|2, at: 'shown'|'revealed'|'advance', scene, line }
                                      → plays entry → peak → (hold | return) on the presentation of `line`
RB.staging.look(actorId, target|null) gaze/torso toward a target without changing collision facing; null = release
RB.staging.pose(actorId, poseId|null) a held posture until cleared or the scene ends
RB.staging.walkTo(actorId, x, y, dir) path-found walk with tile reservation; bounded (3 s); authored fallback stance
RB.staging.prop(propId, 'hold'|'place'|'hide', actorId, hand)   visual attachment only (inventory stays with !give/!take)
RB.staging.frameOf(actor, t) → frame key | null   asked by 60_render.js drawActor() before actorFrame()
RB.staging.settle()                   finish every running gesture at its hold (an early advance)
RB.staging.end(sceneToken)            release owned actors, restore wander/followers, drop props (from 70_script.js run() finally)
```
Ownership: a scene token from `RB.script.run()`; ambient gestures (§15) are a separate low-priority owner that
yields to any scene, battle, puzzle or menu.

**Script ops** (`70_script.js exec()`, `tools/validate.mjs OPS`):

| Op | Meaning | Blocking |
|---|---|---|
| `!gesture <actor> <primitive> [target] [hold] [@revealed\|@advance]` | one primitive on the next line's presentation (or when its text is revealed / on its advance) | no (a `wait` arg blocks to the peak, bounded) |
| `!look <actor> <target\|->` | gaze and torso orientation | no |
| `!pose <actor> <pose\|->` | a held posture | no |
| `!walkto <actor> <x> <y> [dir]` | authored position, path-found, reserved | yes, bounded |
| `!prop <prop> hold\|place\|hide [actor] [hand]` | the visible object in a handover | no |
| `!beat <id>` | a semantic beat id (for review, tests and the manifest) | no |

Cues bind to the line that follows them, so one cue serves every language profile (a scene line holds
`JP || EN`) and Suzu's Kansai lines (swapped at display, `src/lang/85_dialect.js`). `?(cond)` prefixes work on
the new ops as on every command, which keeps branch-specific performance branch-specific. The dialogue
emits the timing points the cues need: `RB.bus.emit('dialogue:line', { sceneId, line, phase: 'shown' |
'revealed' | 'advance' })` from `20_dialogue.js say()`, the end of `reveal()`, and `advance()`.

### 3.5 Illustrated sequence player with manual control — `RB.sequence` (extends `src/ui/42_interlude.js`; new `src/ui/43_sequence.js`, shot art `43a_seq_ch1.js` … `43f_seq_ch6.js`)

- **Declaring shots.** A scene section is wrapped `!sequence <seqId> begin` … `!sequence <seqId> end`; inside,
  `!shot <shotId> [phase]` switches the picture (the existing `!interlude <id> <stage>` keeps working; a shot
  is an interlude stage with a one-time action and a hold). Art registry as today: `RB.interlude.ART[seqId] =
  { shots: { [shotId]: { draw(c, w, h, t, st), action: ms, safe: { wide, narrow } } } }`, where `st = { shot,
  since, k (0..1 through the one-time action, then 1 forever), vb (the sheet's top), still, review }`.
- **States.** `entering → presenting (one-time action) → holding (calm, indefinitely) → advancing | reviewing →
  exiting`. Only the reader's Next leaves `holding`; there is no timer path.
- **Controls** (in the dialogue sheet's `.ctrl` row while `RB.sequence.active()`): Next (the existing
  `b-next`), Previous, Replay shot, Hide text / Show text, Skip scene; on narrow screens Previous/Replay/Hide
  sit in a labelled "Scene" menu button. Keyboard: `ok` = Next (existing), `cancel` = open the Skip/exit
  control (never a silent skip), `log` = History; Previous/Replay/Hide get bindings through
  `RB.input.DEFAULT_BINDS` additions (remappable in Settings › Controls).
- **Next.** `20_dialogue.js advance()` already does (1) reveal, then (2) resolve one line; the shot change (3)
  happens because the next `!shot` command runs after the line resolves; (4) the scene's continuation runs once.
- **Review.** `RB.sequence` records each reached beat `{ shot, line: { who, expr, jp, en }, branchLabel }` as
  `say()` presents it. Previous renders the earlier beat's line and its shot at its hold, without touching
  the runner (its `say()` promise stays pending), so no state command can run; Next walks back to the live
  line and stops there.
- **Replay shot.** Resets `since` for the current shot only; same look snapshot, branch and props.
- **Hide text.** A class on `.dlg` hiding `.txt` while a "Show text" button and navigation stay; it never resolves
  a pending choice (choices stay visible).
- **Skip scene.** `RB.ui.confirm()` when any beat ahead is unseen; then a scoped skip flag fast-forwards
  `say()` lines of this scene only, stopping at `choose()`, `!challenge`, `!activity`, `!battle` and any
  decision; nothing is chosen for the player; seen state is recorded per sequence branch (`s.seq`).
- **Reduced motion.** `still: true` holds key poses; no `!shake` inside a sequence.
- **Prologue.** Uses the same model without a scene: `40_create.js prologue()` drives `RB.prologueArt.draw()`
  with `k` from the one-time action (clamped at 1 for the hold), fades only when the player asks to leave a
  shot, and Escape opens a confirm (SHOTS.md "Prologue").
- **Continuity.** Entering a sequence sets the map state the shots assume (who is present, what is held) by
  ordinary script ops before `begin`; leaving re-enters the world through the same scene's next ops
  (`!refresh`, `!warp` …). The shots read state; they never write it.
- **Replay records.** On `end`, `RB.company.memory(s, { id: 'seq:' + seqId, kind: 'together', title, text, ref: {
  seq, branch: [labels taken], comp, look: <compact selectors>, pet } })` — Company › Shared memories lists
  them and opens a read-only replay (`RB.sequence.replay(ref)`) that runs the shots and recorded lines with
  no scene runner and no state ops. Legacy campaigns that saw a scene before this feature get no invented
  record (an optional "reconstructed" replay must say so).

### 3.8 Mannerism profiles and the idle scheduler (paired addendum; extends §3.4, does not duplicate it)

- **Profiles:** data in `src/content/mannerisms/*.js` (`RB.mannerisms.add(id, profile)`; schema in GESTURES.md §3),

- **Idle scheduler:** part of `RB.staging` (`src/engine/52_staging.js`) as its lowest-priority owner, ticked once
  per world update from `50_world.js` (one call where the random glance runs today, line 624, which it replaces).
  Per actor: the current habit, its next time (seeded from the actor id, like breathing), the pose key it shows.
  It yields at once — clears to the rest pose — when a scene owns the actor, the player interacts, a battle or
  puzzle starts, or a menu opens; it never moves an actor off its tile except for the existing `wander`.
  Social pairs come from optional map data (`pairs: [[idA, idB, { every }]]`) or proximity; contextual reactions
  listen for field-puzzle prop changes (`RB.fieldweave`), arrivals and departures (`50_world.js` walk-ins and
  leaves) and the map's ambience on entry (snow, leaves, embers …).
- **Rendering:** the same pose keys and `RB.staging.frameOf(actor, t)` hook as §3.4 — one renderer path for idle,
  conversation and scenes.
- **Companion and player:** the follower (`W.comp`) and `W.player` read their profiles when idle ≥1.2 s; shared
  stillness is one scheduler rule (both target the prop the player faces, the companion a beat later).

## 6. Risks

1. **Scale of the overworld rig.** A 40 × 58 figure with 3 px arms can show a hand at the chin or a pointed
   arm, but not finger counting or a readable hand-to-mouth laugh without bespoke frames; some primitives
   will read only with a bubble or an illustrated shot. GESTURES.md marks each; Phase D must not count a
   primitive that does not read at play scale (§11.2 "readable distinction").
2. **Two fronts in shared files.** `70_script.js`, `20_dialogue.js`, `tools/validate.mjs` and every scene file
   are edited by B2, D and E and by worker (c)'s music cues. Mitigation: the single-owner table above;
   cues added on their own lines; regenerate the manifest after each merge (its test catches new scenes).
3. **Timing retune vs. invariance.** Lengthening the techniques to 2.2–2.7 s changes when beats are applied;
   rules must not move. `battle_invariance.mjs` and the 20-battle cycle must be re-run after the retune;
   the banner's `bannerOff` follows `P.end` automatically.
4. **Busts' memory.** Two 256 × 224 busts × phases × variants can approach several MiB per pairing; the
   battle addendum's memory budget (37.12–38.58 MiB of 48, docs/battle) leaves ≈9 MiB. Cap the cache by bytes
   and measure with `battle_budget.mjs`.
5. **Manual review without re-running the runner.** The review UI must render past lines while the live
   `say()` promise is pending; any attempt to "replay" through `exec()` would re-run state ops. Keep review
   purely presentational (HX49).
6. **Per-branch seen state.** Today `s.seen[sceneId]` is set when a scene ends, for whatever branch ran;
   skip-seen therefore treats an alternative branch as seen (§18.4). Sequences need `s.seq[seqId].branches`;
   extending the same to all scenes is a separate decision for the lead.
7. **Prologue rework and the existing prologue tests.** `tests/e2e/prologue.mjs` steps through the shots with
   Next and samples `RB.prologueArt.draw(kind, …, k)` at chosen `k` (the traveller on the road, the fading name);
   keep that signature (k = progress of the one-time action) or update the test in the same change, and add the
   60-second idle check (HX69).
8. **Command-index references into scenes.** The comparisons of practice suite B
   (`src/content/practice_b/30_compare.js`, 24 references `{ scene, line: <command index>, h: <hash> }`,
   checked exactly by `tests/unit/practice_b.test.mjs` line 151) point into `rw.bridge_scene` (11),
   `sg.omi_wataru` (9), `sg.wataru_confront` (10), `co.tokiwa_confront`, `rw.tsuru_first`, `sg.omi_intro` and 18
   more. Inserting `!gesture`, `!shot` or `!sequence` commands before a referenced line shifts its index: the
   engine still finds it by hash (`RB.compare.status()` → `'moved'`), but the unit test fails. Whoever adds cues
   to those scenes updates `line` in the same change (the hash does not change). `RB.company.recordAt()`
   (`58_companion.js` line 505) also splices `co_note` hooks at choice labels at load time; never put a cue
   between a `!goto`/`!end`/`!choice` and the label that follows it.
9. **Idle noise and cost.** 199 placements with personal idles can turn into the "parade of gestures" both
   addenda warn against; rates must come from the class overlays (slow for officials and elders), one habit at
   a time, and the busiest maps (`sb.hamlet`, `sb.inn`, `co.eve`, `co.festival`) measured for frame cost and
   sprite-cache growth (pose keys × looks × directions in an LRU).
10. **Portrait readability vs. identity.** The eye fixes change how every character looks in close-up; compare
    before/after sheets for all 87 portrait characters and keep each face recognisable.
11. **Heuristic manifest.** 1,376 of 1,392 classifications are heuristic drafts; Quiet by design is the
   largest class (859). Phase D must review rather than accept them (HX39–HX40).
